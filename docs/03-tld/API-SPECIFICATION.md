## 1. Conventions

### 1.1 Request and response format
- `Content-Type: application/json; charset=utf-8`; property names camelCase; ids are UUID strings; money values are **decimal strings** (`"1234.50"`) with a sibling `currency`; dates `YYYY-MM-DD`; instants ISO-8601 UTC (`2026-11-17T10:15:00Z`).
- Every response carries `X-Request-Id`. Clients may send `X-Request-Id` (UUID); otherwise the server generates one.
- Single resources are returned unwrapped: `{ "id": "...", ... , "rowVersion": 3 }`.
- Collections: `{ "items": [...], "nextCursor": "opaque|null", "totalEstimate": 1234 }` (`totalEstimate` only where cheap; omitted otherwise).

### 1.2 Authentication by surface
| Surface | Mechanism | Failure |
|---|---|---|
| `/api/v1/*` | Better Auth session cookie `crm.session_token` (Secure, HttpOnly, SameSite=Lax, app origin); unsafe methods require `Origin` = app origin | 401 `UNAUTHENTICATED`; 403 `CSRF_ORIGIN_MISMATCH`; 403 `MFA_ENROLMENT_REQUIRED` |
| `/addin/v1/*` (Outlook) | `Authorization: Bearer <addin session token>` (ADR-074/085) | 401 |
| `/addin/v1/gmail/*` | Google-signed ID token in the card request (`authorizationEventObject.userIdToken`) verified per call; mapped to an active invited user | 401 card error |
| `/public/v1/*` | `__Host-bs` buyer session cookie (ADR-071) except `session/exchange`, form endpoints and pixel | 404 `PROPOSAL_NOT_AVAILABLE` (uniform) |
| `/webhooks/esign/{provider}` | Provider signature (HMAC over raw body + timestamp) or ADR-086 baseline | 401 (no detail) |
| `/webhooks/leads/{formKey}` | `X-CRM-Signature: t=<unix>,v1=<hex hmac-sha256(secret, t + "." + body)>` | 401 `WEBHOOK_SIGNATURE_INVALID` / `WEBHOOK_TIMESTAMP_STALE` |

### 1.3 Errors (RFC 9457)
```json
HTTP/1.1 422 Unprocessable Content
Content-Type: application/problem+json
{
  "type": "https://crm.internal/errors/LOST_REASON_REQUIRED",
  "title": "A lost reason is required",
  "status": 422,
  "code": "LOST_REASON_REQUIRED",
  "detail": "Closing a deal as lost requires a reason from the list.",
  "errors": [{ "path": "lostReasonId", "code": "REQUIRED", "message": "Select a lost reason" }],
  "requestId": "0193f0c2-...",
  "meta": {}
}
```
| HTTP | When | Typical codes |
|---|---|---|
| 400 | Malformed JSON / Zod parse failure | `VALIDATION_FAILED` (with `errors[]`) |
| 401 | No/invalid credentials | `UNAUTHENTICATED` |
| 403 | Authenticated but not permitted | `FORBIDDEN`, `VIEW_ONLY`, `FORBIDDEN_REASSIGN`, `MFA_ENROLMENT_REQUIRED`, `CSRF_ORIGIN_MISMATCH` |
| 404 | Not found **or not visible** (never reveal existence of out-of-scope records) | `NOT_FOUND`, `PROPOSAL_NOT_AVAILABLE` |
| 409 | State conflicts | `CONCURRENT_MODIFICATION`, `INVALID_STATE_TRANSITION`, `IDEMPOTENCY_KEY_REUSED`, `SIGNATURE_REQUEST_ALREADY_OPEN`, `DRAFT_VERSION_EXISTS`, `CONFIRMATION_REQUIRED`, `RESPONSE_ALREADY_RECORDED` |
| 410 | Gone (expired invitation/export link) | `INVITATION_EXPIRED`, `EXPORT_LINK_EXPIRED` |
| 413 | Payload too large | `IMPORT_FILE_TOO_LARGE`, `AI_INPUT_TOO_LARGE` |
| 422 | Business-rule violation | module codes (BUSINESS-RULES §20) |
| 428 | Required precondition header missing | `IDEMPOTENCY_KEY_REQUIRED` |
| 429 | Rate/budget limit | `RATE_LIMITED`, `AUTH_RATE_LIMITED`, `AI_QUOTA_EXCEEDED`, `RESEND_THROTTLED` (+ `Retry-After`) |
| 502/503 | Provider failure / maintenance | `ESIGN_PROVIDER_ERROR`, `AI_PROVIDER_UNAVAILABLE`, `PROVIDER_SEND_FAILED` |

Warnings that need user confirmation (e.g. `DEAL_AMOUNT_DIFFERS`, `DISCOUNT_LIMIT_EXCEEDED`, `OPEN_SIGNATURE_REQUEST_CONFIRM`, `DUPLICATE_SUSPECTED`) are returned as **409 `CONFIRMATION_REQUIRED`** with `meta.confirmations: [{code, message, data}]`; the client repeats the request with `"confirm": ["<code>", ...]` in the body.

### 1.4 Pagination, sorting, filtering
- `GET` collections accept `limit` (1–100, default 25), `cursor` (opaque base64url of the last sort key + id), `sort` (comma-separated, `-` prefix descending; allowed fields documented per endpoint; tie-breaker `id` appended automatically).
- Filters are explicit query parameters per resource (e.g. `ownerId`, `stageId`, `status`, `closeDateFrom`, `q`). Multi-values repeat the parameter (`status=open&status=won`). Custom-field filters: `cf.<key>=<value>` (equality), `cf.<key>.gte` / `.lte` for number/currency/date.
- `viewId=<savedViewId>` applies a saved view's filters/sort (BR-CRM-011); explicit params override.
- All collections are permission-scoped (ADR-076); filters can only narrow.

### 1.5 Idempotency
- Header `Idempotency-Key: <uuid>` **required** (428 otherwise) on: proposal send prepare/commit, mark shared manually, signature request create, signature resend, email send, import commit, import undo, export start, buyer accept/decline, AI accept, automation reversal, bulk operations.
- Stored in `idempotency_key` for 24 h scoped to `userId|route` (buyer: `buyerSession|route`). Same key + same request hash → replay of the stored status and body; same key + different hash → 409 `IDEMPOTENCY_KEY_REUSED`; in-progress → 409 with `Retry-After: 1`.

### 1.6 Optimistic concurrency
Mutable resources expose `rowVersion`. `PATCH`/state-change requests must include `rowVersion`; mismatch → 409 `CONCURRENT_MODIFICATION` with `meta.current` (latest representation the actor may see).

### 1.7 Versioning and deprecation
Path version `v1`. Additive changes only within v1 (new optional fields, new endpoints). Breaking change → `v2` path running in parallel for one release; deprecated endpoints send `Deprecation` and `Sunset` headers.

### 1.8 Rate limits (ADR-026)
| Route class | Limit |
|---|---|
| `/auth/sign-in/*`, password reset, TOTP verify | 10/min per IP and 5/min per account (Postgres bucket); lockout per RULE-PLT-08 |
| `/api/v1/*` general | 600/min per user (LB) |
| AI endpoints | Budget-based (ADR-043) + 30/min per user |
| `/public/v1/session/exchange` | 30/min per IP |
| `/public/v1/identity`, `/verify` | 10/h per link (identity), 5 attempts per code, 3 codes/h per session |
| `/public/v1/views/heartbeat` | in-memory, 1 per 10 s per session |
| `/public/v1/forms/{key}/submissions` | `spamProtection.rateLimitPerIpPerHour` (default 10) per IP per form |
| `/webhooks/*` | 600/min per provider |

## 2. Common schemas (packages/shared)

```ts
type Uuid = string;                      // UUIDv7
type Money = { amount: string; currency: string };   // amount decimal string
type ActorRef = { actorType: 'user'|'buyer'|'system'|'ai'; userId?: Uuid; displayName: string; systemComponent?: string };
type RecordRef = { type: 'company'|'contact'|'deal'; id: Uuid };
type UserSummary = { id: Uuid; fullName: string; email: string; role: Role; status: 'invited'|'active'|'deactivated' };
type Role = 'admin'|'sales_manager'|'salesperson';
type Page<T> = { items: T[]; nextCursor: string | null; totalEstimate?: number };
type Permissions = { can: Record<PermKey, boolean>; scopes: { companies: Scope; contacts: Scope; deals: Scope } };
type Scope = 'all'|'team'|'own'|'own_plus_view_only';
type CustomFieldValues = Record<string, string | number | boolean | string[] | Money | null>;
type Rich = { type: 'doc'; content: unknown[] };   // ProseMirror JSON (schemaVersion in parent)
```
Each resource representation includes `permissions` (the actions the caller may perform on that record, e.g. `{"edit":true,"reassign":false,"close":true}`) so the UI never re-derives authorization (ROLE-PERMISSION-MATRIX §7).

Same shape as companies: `GET/POST /api/v1/contacts`, `GET/PATCH /api/v1/contacts/{id}`, `/archive`, `/restore`, `/owner` (PERM-042..046), `/timeline`.
```ts

  mobilePhone?: string; jobTitle?: string; companyId?: Uuid | null; ownerId?: Uuid; customFields?: CustomFieldValues; confirm?: string[] };
```

Validation: at least one of firstName/lastName/email; email RFC 5322 and unique among active contacts (`CONTACT_EMAIL_TAKEN`, OD-60); companyId must be visible and not archived.

Server validation order: proposal status sendable (`PROPOSAL_NOT_SENDABLE`), draft exists, pre-send check fresh for the current content hash with zero blocking findings (`PRESEND_BLOCKING_FINDINGS`, RULE-AIA-11, OD-56); failures are returned as 409 `PROPOSAL_NOT_SENDABLE` with `meta.reasons[]` per RULE-PRP-08, recipients valid (`NO_RECIPIENTS`), mailbox connected for `crm_email` (`MAILBOX_NOT_CONNECTED`), confirmations.
