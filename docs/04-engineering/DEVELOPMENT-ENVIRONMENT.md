# Development Environment — Internal Sales CRM (Phase 1, Windows)

**Not set up yet** — this is the specification for the implementation phase.

## 1. Workstation prerequisites (Windows 11)
| Tool | Version | Notes |
|---|---|---|
| Git for Windows | 2.5x | `core.autocrlf=false`, `.gitattributes` with `* text=auto eol=lf` (scripts, SQL, snapshots must be LF) |
| Node.js | 26 LTS | via `winget install OpenJS.NodeJS.LTS` or `fnm` (`fnm use` reads `.node-version`) |
| pnpm | 12.x | `corepack enable` then `corepack prepare pnpm@12 --activate` (version pinned in `packageManager`) |
| Docker Desktop | current, WSL 2 backend | Runs Postgres, MinIO, Mailpit and provider fakes |
| VS Code | current | Extensions: Biome, Tailwind CSS IntelliSense, Playwright Test, Docker, PostgreSQL client (or DBeaver/pgAdmin) |
| PowerShell 7 or Git Bash | — | All repo scripts are Node-based, so either shell works |
| k6 (optional) | current | Load tests |

**Repository location:** clone to a path **outside OneDrive**, e.g. `C:\dev\sales-crm` (ADR-033). Add the repo folder to Windows Defender exclusions for build speed (developer's choice, with IT approval). Enable long paths: `git config --system core.longpaths true`.

## 2. Local services (docker-compose.yml)
| Service | Image | Port | Purpose |
|---|---|---|---|
| `postgres` | `postgres:18` | 5432 | App DB (`crm_dev`), test DBs (`crm_test_*`); init script creates roles `crm_migrator`, `crm_app`, `crm_renderer`, `crm_sealer`, `crm_readonly` with dev passwords |
| `minio` | `minio/minio` | 9000/9001 | S3-compatible storage (versioning + object lock enabled bucket `crm-dev`) |
| `mailpit` | `axllent/mailpit` | 1025 SMTP / 8025 UI | Captures transactional emails (TransactionalEmail SMTP driver in dev) |
| `fake-esign` | local image from `apps/server/test/fakes/esign` | 4010 | Provider simulator: envelopes, signer actions UI, signed webhooks |
| `fake-ai` | local image from `test/fakes/ai` | 4020 | Deterministic streaming/JSON responses (optional; real Anthropic key usable with dev budget) |
| `fake-mail` | local image from `test/fakes/mail` | 4030 | Gmail/Graph delta + send simulator for local development without real mailboxes |
Fakes are **development and test tools only**; production code paths use the real adapters selected by configuration, and staging uses real provider sandboxes.

## 3. Local configuration (`.env.local`, never committed)
Copied from `.env.example`. Dev values: `APP_ORIGIN=http://localhost:5173` (Vite proxy to server `:3000`), `BUYER_ORIGIN=http://proposals.localhost:5174`, `DATABASE_URL=postgres://crm_app:dev@localhost:5432/crm_dev`, `DATABASE_URL_MIGRATOR=…crm_migrator…`, `STORAGE_DRIVER=s3` + MinIO endpoint, `TXEMAIL_PROVIDER=smtp` (Mailpit), `ESIGN_PROVIDER=fake`, `AI_PROVIDER=anthropic|fake`, `KEYRING_LOCAL_MASTER_KEY=<generated by script>`, `BETTER_AUTH_SECRET=<generated>`. Google/Microsoft OAuth for local login uses dev client ids with `http://localhost` redirect URIs registered in the company tenant (IT) — or password login only in local dev.
`*.localhost` hostnames resolve to 127.0.0.1 in modern browsers, giving two distinct origins (app vs buyer) locally without hosts-file edits.

## 4. First-time setup (later phase)
```
corepack enable
pnpm install
pnpm dev:services            # docker compose up -d
pnpm db:migrate
pnpm db:bootstrap -- --org-name "Our Company" --currency USD --timezone "America/New_York" --admin-email you@company.com
pnpm dev                     # server :3000, worker, renderer, web :5173 / :5174
```
The bootstrap prints a one-time invitation link for the first Admin.

## 5. Daily workflow
| Task | Command |
|---|---|
| Run everything | `pnpm dev` |
| Schema change | edit `apps/server/src/db/schema/*.ts` → `pnpm db:generate` → review SQL → `pnpm db:migrate` |
| Tests | `pnpm test` (unit/integration), `pnpm test:e2e` (needs services running) |
| Lint/format/boundaries | `pnpm lint`, `pnpm format`, `pnpm boundaries` |
| OpenAPI + client types | `pnpm openapi` |
| Reset local DB | `pnpm db:reset` (drops and recreates `crm_dev`, migrates, bootstraps) |
| Inspect jobs | Admin UI `/admin/data` → Jobs, or SQL on `pgboss.job` |
| View emails | Mailpit UI http://localhost:8025 |

## 6. Windows-specific notes
- Playwright Chromium for local PDF rendering: `pnpm exec playwright install chromium` (renderer runs locally without network sandboxing; the no-egress guarantee is enforced in deployed environments — tests assert the request interception guard).
- `sharp` ships Windows prebuilt binaries; no build tools needed.
- File watching: Vite and `tsx watch` work on NTFS; avoid OneDrive/network drives.
- Line endings: Biome enforces LF; PDF golden files and SQL use LF.
- Docker Desktop memory ≥ 6 GB (Postgres + MinIO + fakes + Chromium tests).

## 7. Branching and CI (summary)
Trunk-based with short-lived feature branches and PRs; conventional commits; required checks per TESTING-STRATEGY §6; preview environments optional. Database migrations are reviewed like code (expand/contract, ADR-052).
